# Claimora Database Documentation

## Overview
Claimora utilizes **PostgreSQL** as its enterprise relational database. The schema is normalized, strongly constrained, and strictly validated.

> **CRITICAL RULE**: `schema.sql` is the **single source of truth** for database structure. Hibernate is configured with `spring.jpa.hibernate.ddl-auto=validate`. Developers must **never** let Hibernate auto-generate or alter production/dev schema. All schema adjustments must be made in `schema.sql`.

---

## Schema Architecture & Tables

| Table | Entity Owner | Description | Primary Key | Key Constraints |
| :--- | :--- | :--- | :--- | :--- |
| **`users`** | **Vidhi** | System users, admins, claims staff, and fraud investigators. (Named `users` to prevent keyword collisions with SQL standard). | `user_id` (identity) | `email` UNIQUE, `role` CHECK, `status` CHECK |
| **`product`** | **Shaili** | Covered products, serial numbers, purchase dates, warranty validity windows. | `product_id` (identity) | `serial_number` UNIQUE, `CHECK (warranty_end >= warranty_start)` |
| **`claim`** | **Tanishka** | Central warranty claims linking claimants, products, status, and issue descriptions. | `claim_id` (identity) | `claim_number` UNIQUE, FKs to `product` & `users`, `status` CHECK |
| **`evidence_document`** | **Kalp** | Uploaded invoices, photos, repair estimates, digital file hashes, and OCR JSON payloads. | `document_id` (identity) | FK to `claim`, non-unique index on `file_hash` for duplicate/fraud detection |
| **`finding`** | **Chinmay** | Risk rules fired, tamper flags, anomalies, and severity scoring generated by fraud analysis. | `finding_id` (identity) | FK to `claim`, `severity` CHECK, `status` CHECK |
| **`investigation_action`** | **Anuj** | **Append-only** audit log capturing investigator decisions, status transitions, and forensic notes. | `action_id` (identity) | FK to `finding`, FK to `users` |
| **`evidence_link`** | *Shared Integration* | Join table associating specific findings with one or more supporting evidence documents. | `(finding_id, document_id)` | Composite PK, FKs to `finding` & `evidence_document` |

## Setup & Execution

### 1. Create PostgreSQL Database
Connect to your local PostgreSQL instance (e.g. using `psql`, pgAdmin, or DBeaver):
```sql
CREATE DATABASE claimora;
```

### 2. Apply Schema
```bash
# Windows PowerShell
psql -U postgres -d claimora -f database/schema.sql
```

### 3. Apply Fictional Seed Data
```bash
# Windows PowerShell
psql -U postgres -d claimora -f database/seed.sql
```

## Environment Variables
The Spring Boot backend connects to the database via environment variables with safe development defaults:

| Variable | Description | Safe Default |
| :--- | :--- | :--- |
| `DB_URL` | JDBC Connection String | `jdbc:postgresql://localhost:5432/claimora` |
| `DB_USERNAME` | PostgreSQL User | `postgres` |
| `DB_PASSWORD` | PostgreSQL Password | `postgres` |
